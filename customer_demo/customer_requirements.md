# Fictional customer requirements

The fictional French group finance team consolidates three entities in EUR and GBP. Its controller wants a traceable pilot before evaluating a broader consolidation solution. These are synthetic portfolio requirements, not client testimony.

| ID | Requirement | V1 acceptance evidence |
|---|---|---|
| R1 | Centralize entity reporting and reduce repeated Excel copying | Four CSV sources; all three entities represented in the workbook |
| R2 | Automate approved FX conversion | UK local values, rate types, rates and EUR values visible |
| R3 | Improve intercompany matching | Reciprocal service and balance pairs matched; discrepancies stop reporting |
| R4 | Trace consolidation adjustments | Three journal IDs, explanations, debits/credits and zero differences |
| R5 | Produce consolidated P&L and balance sheet | Revenue €4.46m; assets €4.04m; balanced statement |
| R6 | Explain minority interests | Germany's 20% profit and equity shares visible |
| R7 | Improve close reliability | Five dashboard controls pass; invalid input tests fail clearly |
| R8 | Support browser-based review | Standard XLSX with precomputed values; no desktop Excel dependency |

The controller reviews rates, intercompany results, journals and output. Entity accountants own submissions; a finance systems analyst runs the pipeline. V1 does not implement access control, approval workflow or a production audit system. Any time savings or close improvements require measurement in a future pilot; they are not claimed results.
